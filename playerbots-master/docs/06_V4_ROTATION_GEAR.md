# v4 — боевая ротация и авто-экипировка

Бот теперь не просто «иногда жмёт спел», а крутит полноценную ротацию вокруг GCD,
понимает каст-таймы, поддерживает DoT/дебаффы, сжимает бурст-кулдауны по условию
и сам надевает лучший шмот из сумок под свой класс брони.

Всё написано под **официальный TrinityCore master** (клиент 12.x), всё собирается
из скриптов — никаких патчей ядра сверх раннего `patches/0001-core-integration.diff`.

---

## 1. Ротационный движок

### 1.1. Приоритет каждого тика (в порядке проверки)

| Шаг | Что делает | Знание/условие |
|-----|------------|----------------|
| 1 | `TryInterrupt` | спел `Kind::Interrupt`, цель кастует → сбить |
| 2 | `TryDefensive` | `Kind::Defensive` (selfHpMax ~35%), при просадке HP бота |
| 3 | `TryHeal` | `Kind::Heal`: себя при HP<60%, мастера/группу при HP<50% |
| 4 | `TryAttackSpell` | `Kind::DoT` → `Debuff` → `Damage` (sort по priority, обратно) |
| 5 | автоатака | melee — `Attack()`, кастер — идти в рендж спела |

### 1.2. GCD и каст-тайм — настоящие

- После успешного каста AI молчит **`max(SpellInfo::StartRecoveryTime, 1500мс)`** —
  это и есть реальный GCD (haste-коррекцию ядро уже применяет при касте; пока читаем
  статические значения SpellInfo, дробные GCD рогов/фералов — в roadmap).
- Если у спела `CalcCastTime() > 0`, бот **полностью останавливается**
  (`MovementStop/MoveIdle`) на время каста и не пытается бежать — в терминах игры
  это «стоять в касте». После каста движение/follow восстанавливается.
- Неуспешные касты (нет ресурса/LoS/иммун) заносятся в **перкомбатный blacklist**
  (`m_castBlacklist`), чтобы AI не спамил 30 раз в секунду один и тот же упавший каст.
  Blacklist сбрасывается при выходе из боя. Точный SpellCastResult → точный blacklist —
  отложено: сейчас blacklist пишется через хук `RegisterCastFail`, который ловит
  только результат `CastSpell != SPELL_CAST_OK`.

### 1.3. DoT и дебафф-management

`maintainAura == true` → перед кастом проверяется
`target->HasAura(spellId, bot->GetGUID())`. Аура есть (ваша!) — спел в этот тик
пропускается, ротация идёт ниже по списку. Ауры чужих кастеров не считаются
(caster GUID сравнивается), так что два бота не «укрывают» DoT друг друга.

### 1.4. Burst-кулдауны

- Спел автоматически помечается `burst = RecoveryTime >= 60 сек` (Bloodlust,
  Berserk, Army of the Dead и т.п. попадают сами, без ручного конфига).
- Burst жмётся только в окне:
  - **первые 8 секунд боя** (`NotifyCombatEnter` ставит `m_burstWindowUntil`), **или**
  - цель опустилась ниже **30% HP** (фаза добивания).
- По внутреннему приоритету burst-спел получает +400, так что в окне он
  обязательно выиграет слот GCD над обычными нюками.

## 2. Авто-экипировка (`EquipBestItems`)

### 2.1. Логика

- Скан сумок: `INVENTORY_SLOT_ITEM_START..END` основных бэгов (bag 255, слоты 35..62).
- Скор предмета: **`baseItemLevel * 10 + quality`** (простой и устойчивый; стат-скоринг
  по классам — в roadmap).
- Кандидат ставится, если `score(candidate) > score(current) + 5` (запас против
  перманентного дёргания одинаковых вещей). До 8 проходов за вызов — ловит цепочки
  замен (снял шапку → понизился шмот в другом слоте — не ловим, но и не нужно).
- Переодевание через `SwapItem(itemPos, EQUIPMENT_SLOT_x)` — ядерная механика,
  все проверки bind-on-equip/сокетов остаются на совести ядра.

### 2.2. Фильтр брони по классу (важно для retail)

Максимально доступный subclass брони:

| Классы | subclass | Броня |
|--------|----------|-------|
| Warrior(1), Paladin(2), DK(6) | 4 | Plate |
| Hunter(3), Shaman(7) | 3 | Mail |
| Rogue(4), Monk(10), DH(12), Druid(11) | 2 | Leather |
| Mage(8), Priest(5), Warlock(9), Evoker(13) | 1 | Cloth |

Всё «ниже» разрешено (mail-юзер может носить кожу/ткань), выше — нет.
Оружие и аксессуары фильтруются только по equip-слоту.

### 2.3. Когда срабатывает

- автоматически — при входе бота в мир (ctor AI, один раз);
- вручную — `.playerbots equip <имя>`.

## 3. Отложенное (roadmap, без кода сейчас)

| Тема | План | Сложность |
|------|------|-----------|
| GCD хаст-корректный | читать модифицированный GCD через SpellHistory/ауру хаста | S |
| Точный blacklist | использовать `SpellCastResult` результат, иммуны/LoS карантинить отдельно | S |
| Статы-скоринг шмота | per-class веса (agi/str/int/crit/haste...) из ItemStats | M |
| Weapons per class | фильтр по skill lines (AddWeaponProf) — аналогично броне | S |
| Босс-механики | engine: таблица `playerbots_boss_rules` (entry, event/aure/timer, action: move-to/cast/stop-dps), reactors на `NotifySpellHit/AreaTrigger` | L |
| Роуты/патрули | таблица `playerbots_route_points` + режим follow-route с waypoint-callback | M |
| Encounter-данные боссов | контент per-instance (бесконечная работа — proof-of-concept сделать на 1 боссе по запросу) | XL |
| Whisper-управление | команды боту в личку («come», «buff me», «equip») | M |
| Компаньоны | pet-боты поверх базы playerbots — отдельный этап | XL |

## 4. Runtime-команды (итог на v4)

| Команда | Что делает |
|---------|-----------|
| `.playerbots add <имя>` | вход бота из characters |
| `.playerbots del <имя>` | выход |
| `.playerbots list` | кто онлайн |
| `.playerbots follow <имя>` | follow-режим на мастера |
| `.playerbots stay <имя>` | стоять |
| `.playerbots book <имя>` | известное знание класса (booking) |
| `.playerbots equip <имя>` | переодеться из сумок под класс |
