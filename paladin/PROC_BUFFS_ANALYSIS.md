Важно про «шанс»: все шесть — **гарантированные талантовые проки (100%), не PPM**. То есть «с каким шансом» = «всегда, если каст триггера прошёл, и баф ещё не висит». Если баф уже активен, повторный триггер **не создаёт новую строку APPLIED** (возможен REFRESH) — это учтено в методике сверки ниже.

## 2. Цепочки по спекам

**Ретрибуция:**
```
Пробуждение зол (255937)
  └─► баф Молот Света [427441] (20с)          ← cast 255937 → AURA_APPLIED 427441
        └─► каст Молота Света (427453)
              └─► баф Неоспоримое постановление [432629] (+12% хаст,6с)
Божественный звон (375576)
  └─► баф Божественный резонанс [386730] (15с)
        └─► Правосудие (20271) ×3 с интервалом5с
```

**Защита:**
```
Карающий щит (31935)
  ├─► баф Оплот порядка [209388] (щит,8с)
  └─► баф Оплот праведного гнева [386652] (стаки,15с, Can Proc From Procs)
Божественный звон → Бож. резонанс → каждые5с Карающий щит (и он снова прокает оба Оплота!)
```

**Свет:**
```
Слово благословения (85673) → баф Свет титанов [378412] (ХоТ,10с)
Божественный звон → Бож. резонанс → Святая вспышка (20473) ×3
```

## 4. Как выглядит корректная пара в логе PalDump

```
[12:00:01] SPELL_CAST_SUCCEEDED Пробуждение зол [255937] Я ->
[12:00:01] AURA_APPLIED Молот Света [427441] Я ->
[12:00:03] SPELL_CAST_SUCCEEDED Молот Света [427453] Я ->
[12:00:03] AURA_APPLIED Неоспоримое постановление [432629] Я ->
```
При проке «поверх висящего бафа» ожидаем `AURA_REFRESH` вместо `AURA_APPLIED`.

## 5. Методика сверки (три уровня)

**Уровень1 — сервер (SQL).** Файл `PROC_VERIFICATION.sql`: выполняешь в HeidiSQL/mysql
против БД **hotfixes** (таблицы `spell`, `spell_effect`, `spell_proc`) и **world**
(`spell_script_names`, `spell_scripts`) без остановки сервера. Сверяем:
- `spell_proc`: есть ли строка-триггер, её `Chance` (=100 ожидаем);
- `spell_effect` с `EffectMiscValue` = ID бафа: какой спелл накладывает баф (обратный поиск триггера);
- `spell_script_names`: не висит ли на этих спеллах кастомный скрипт (в т.ч. наш `spell_paladin_class_fixes_*`).

**Уровень2 — клиент (PalDump v4.11).** После боя:
```
/paldumplog clear
...драться10–20 сек (все6 бафов должны прокнуть)...
/paldumplog procs
```
Команда печатает по каждому бафу: сколько раз накладывался (`APPLIED`), обновлялся (`REFRESH`)
против скольких кастов его триггера.

**Уровень3 — я.** Присылаешь: (а) вывод `procs`, (б) результат SQL из п1 файла.
Сверяю три числа: **ожидание из таблицы §1 = SQL-конфигурация сервера = поведение в логе**.
Расхождение в любую сторону = либо баг вилки (сервер прокает иначе DBC),
либо лог ловит не всё — и по разнице видно, какой именно триггер «тихий».

## 6. Пороги, по которым считаем «всё ок»

- `Молот Света` (триггер Пробуждение зол): `накладывался ≈ касты255937` (минус окно20с);
- `Неоспоримое постановление` (триггер Молот427453): `накладывался ≈ касты427453`;
- `Свет титанов` (триггер85673): `накладывался + refresh ≈ касты85673`;
- `Божественный резонанс` (триггер Divine Toll): `накладывался ≈ касты375576`; тики20271/31935/20473
  после него ≈ **3 на каждый** накладыватель (интервал5с, окно15с);
- `Оплот порядка` + `Оплот праведного гнева` (триггер31935): накладываний ≤ кастов31935
  (щит бьёт до4 целей, но прок бафа — один на каст; разница = окна8с/15с и уже висящие стаки).
