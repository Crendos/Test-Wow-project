## 5. Методика сверки (три уровня)

**Уровень1 — сервер (SQL).** Файл `PROC_VERIFICATION.sql`: выполняешь в HeidiSQL/mysql
против БД **hotfixes** (таблицы `spell`, `spell_effect`, `spell_proc`) и **world**
(`spell_script_names`, `spell_scripts`) без остановки сервера. Сверяем:
- `spell_proc`: есть ли строка-триггер, её `Chance` (=100 ожидаем);
- `spell_effect` с `EffectMiscValue` = ID бафа: какой спелл накладывает баф (обратный поиск триггера);
- `spell_script_names`: не висит ли на этих спеллах кастомный скрипт (в т.ч. наш `spell_paladin_class_fixes_*`).

**Уровень2 — клиент (PalDump v4.11).** После боя:
```
/paldumplog clear
...драться10–20 сек (все6 бафов должны прокнуть)...
/paldumplog procs
```
Команда печатает по каждому бафу: сколько раз накладывался (`APPLIED`), обновлялся (`REFRESH`)
против скольких кастов его триггера.

**Уровень3 — я.** Присылаешь: (а) вывод `procs`, (б) результат SQL из п1 файла.
Сверяю три числа: **ожидание из таблицы §1 = SQL-конфигурация сервера = поведение в логе**.
Расхождение в любую сторону = либо баг вилки (сервер прокает иначе DBC),
либо лог ловит не всё — и по разнице видно, какой именно триггер «тихий».

## 8. 🐛 ИЗВЕСТНЫЙ БАГ (репорт от26.09.2026): накладываются «с любой способности»

**Симптом:** `386730 Божественный резонанс`, `427441 Молот Света`, `432629 Неоспоримое
постановление` накладываются на игрока **с ЛЮБОЙ способности, включая призыв
ездового животного**. Так не должно быть: у каждого строго свой триггер (§1).

**Почему это баг сервера, а не DBC:**
- №3/№9 показали: на аплееры `427445/432626/386732` в DBC **никто не ссылается**
  широким образом — их кидают только скрипты (`spell_pal_wake_of_ashes`,
  `spell_pal_hammer_of_light_ex`, `spell_pal_divine_resonance_prot_ex` и т.п.);
- `world.spell_proc` пусто — кастомных широких правок в SQL нет;
- значит, событие-источник шире нужного находится **в коде C++** (хук вида
  «OnSpellCast любого спелла» вместо «каст конкретного триггера»).

**План отлова:**
1. **Клиентский эксперимент (3 мин):** `/reload` → `/paldumplog clear` →
   **ни одного боя** → призвать маунта → `/paldumplog show 30`.
   Ожидаем пару: `SPELL_CAST_SUCCEEDED <маунт>` → `AURA_APPLIED ... [386730/427441/432629]`
   — это точный «отпечаток» виновника.
2. **Поиск в исходниках сервера** (выполняет владелец сервера, вывод сюда):
   ```
   findstr /s /i /c:"427445" /c:"432626" /c:"386732" /c:"386738" *.cpp *.h
   findstr /s /i /c:"386730" /c:"427441" /c:"432629" *.cpp *.h
   ```
3. **SQL:** исправленный №8 (`spell_linked_spell`, колонка `SpellId`) + расширенный
   поиск скриптов по именам (см. реплику задания).

###8.1 Расследование по нашим файлам (paladin/*.cpp,26.09.2026)

Кто из НАШИХ скриптов вообще умеет кастить эти три бафа:

| Баф | Кастер в наших файлах | Привязка (наши SQL) | Проверка условия |
|---|---|---|---|
| `386730` Резонанс | `spell_pal_divine_toll_ex::HandleAfterCast` (fix_6) | только `375576` Божественный звон | `HasAura(386738)` ✓ |
| `432629` Неоспоримое | `spell_pal_hol_templar_ex::HandleAfterCast` (fix_9) | только `427453` Молот Света | **`HasSpell(432626)` — какого спелла НЕ проверяет** |
| `427441` Молот Света (баф) | **в наших файлах НЕТ ни одного каста** (427445 только читается как `HasAura`) | — | кастер = код вилки |

**Вывод:** наши SQL-биндинги узкие; если бафы падают «с любой способности», то
либо (а) в world БД есть **лишние строки** `spell_script_names` для этих ScriptName
(не из наших SQL — проверка: `SELECT * FROM spell_script_names WHERE ScriptName IN (...)`),
либо (б) широкий хук в **коде вилки** (findstr выше — особенно `427445/427441`:
это единственный баф, которого нет в наших исходниках).
Фикс после подтверждения: лишние биндинги — удалить; широкий хук вилки — уточнить
установкой `if (GetSpell()->Id != ...)` в наши AfterCast + пересборка.

###8.4 ✅ КОРЕНЬ ПРИЧИНЫ УСТАНОВЛЕН (26.09.2026)

| Улика | Результат | Вывод |
|---|---|---|
| `spell_aura_options` | **427445 `ProcTypeMask2=4`, 432626 `ProcTypeMask2=4`, 386732 `ProcTypeMask1=2446336` (0x255380)** — широкие маски; честный **378405 =16384/0 (узкий)** | 🎯 три виновных бафа = три ауры с широким проком; чистый баф — с узким |

**Механизм:** пассивная талантовая аура висит на игроке → её `ProcTypeMask`
содержит бит «успешный каст чего угодно» → любой каст (в т.ч. маунт) → прок →
эффект ауры накладывает баф. **Легитимные пути не через эти маски:**432629 даёт
наш `hol_templar_ex` (после Молота),386730 — наш `divine_toll_ex` (после Звона).

**Фикс:** `paladin/PROC_FIX.sql` — `UPDATE spell_aura_options SET ProcTypeMask1=0,
ProcTypeMask2=0 WHERE SpellID IN (427445,432626,386732)` + перезапуск worldserver
(кэш hotfix). Тест после: маунт → ничего; Звон → Резонанс ✓; Молот → Неоспоримое ✓;
Пробуждение зол → Молот Света (если пропал — добавим узкий grant-скрипт).
